1. 시스템 설계 구조 및 추상화 인터페이스 (BaseManager)
--------------------------------------------------------------------------------
모든 데이터 관리 클래스(Manager)의 확장성 확보 및 다형성 보장을 위해 최상위 추상 클래스를
정의하고, 이를 모든 매니저 클래스가 상속받도록 강제합니다.

■ BaseManager 클래스 (BaseManager.h) 필수 규격
  - 가상 소멸자 정의: 자식 객체 소멸 시 메모리 누수를 방지하기 위해 필수 지정
    * virtual ~BaseManager() = default;
  - 순수 가상 함수 선언: 자식 클래스에서 반드시 오버라이딩하도록 구현을 강제함
    * virtual void loadFromFile() = 0;
    * virtual void saveToFile() = 0;
    * virtual int size() = 0;

■ 상속 적용 대상 및 구현 제약
  - MovieManager, UserManager, RatingManager 클래스는 BaseManager를 반드시 상속받아야 함.
  - 헤더(.h)와 소스(.cpp) 파일을 명확히 분리하여 설계할 것.
  - 각 오버라이딩 함수에는 명시적으로 'override' 키워드를 붙여 컴파일 타임 검증을 강화할 것.
  - 외부 파일(CSV 형식)과의 데이터 연동 및 파싱 로직을 내부적으로 포함해야 함.
  - BaseManager는 인스턴스화가 불가능해야 함 (단독 객체 생성 금지).

2. 핵심 연산 및 알고리즘 사양 (Recommender 클래스)
--------------------------------------------------------------------------------
두 사용자 간의 취향 성향 차이를 정량화하고, 이를 바탕으로 개인화된 영화 목록을 추천합니다.

2.1 사용자 간 유사도 연산 (Similaritycalculate)
  - 함수 시그니처:
    int Similaritycalculate(const vector<Rating>& ratingsA, const vector<Rating>& ratingsB);
  - 핵심 로직 및 최적화 조건:
    1. 데이터 복사 비용을 방지하고 무결성을 유지하기 위해 'const vector<Rating>&' 참조자 형태 사용.
    2. 두 사용자(A, B)가 공통으로 평점을 남긴 동일 영화(movieId) 목록을 완전 탐색함.
    3. 공통 영화가 발견되면 |평점A - 평점B| (두 평점 차이의 절대값)을 구하여 누적합(Accumulate) 계산.
    4. 공식의 표준에 따라 최종 누적된 정수형(int) 차이값을 반환 (차이가 작을수록 유사도가 높음).

2.2 영화 추천 파이프라인 (recommend)
  - 함수 시그니처:
    vector<int> recommend(int targetUserId, int K, int N); (또는 시스템 규격에 맞춘 영화 ID 목록 반환형)
  - 5단계 흐름 가이드:
    [Step 1] 대상 사용자 예외 확인
            추천 대상 사용자(Target User)의 기존 평점 이력이 전혀 없는 경우(vector.empty()),
            후속 알고리즘을 수행하지 않고 즉시 빈 목록을 반환하여 불필요한 연산 낭비 방지.
    [Step 2] 유사도 전수 조사
            시스템 내부의 전체 사용자 데이터를 순회하며, 추천 대상 사용자 본인을 제외한
            모든 사용자와의 Similaritycalculate() 결과를 계산하여 데이터 구조에 저장.
    [Step 3] 상위 K명 이웃 선정
            수집된 취향 차이값 점수를 기준 삼아 오름차순(차이가 가장 적은 순)으로 정렬 수행.
            정렬 시 람다식(Lambda Expression)을 적용하며, 최상위 K명의 핵심 이웃을 추출함.
    [Step 4] 후보 영화 풀(Pool) 구축
            선정된 상위 K명의 이웃들이 남긴 평점 기록을 탐색하되, 추천 대상 사용자가 이미 관람하여
            평점을 남긴 영화는 제외하고 '미관람 영화'들만 후보 풀에 등록함.
    [Step 5] 점수 누적 및 상위 N개 추출
            이웃들의 평점 수치를 기반으로 후보 영화들의 누적 추천 점수를 연산 및 합산함.
            최종 합산 점수를 내림차순(점수가 높을수록 강력 권장) 정렬하여 상위 N개의 영화 ID를 반환.

3. 필수 활용 C++ 문법 및 고성능 데이터 구조 표준
--------------------------------------------------------------------------------
AI Agent는 코드를 자동 생성할 때 Modern C++ 표준에 맞추어 아래 STL 구조를 명확히 반영해야 합니다.

  - std::pair
    * (사용자 ID, 유사도 값) 또는 (영화 ID, 누적 점수) 등의 쌍 데이터를 단일 레코드로 묶을 때 사용.
  - std::set
    * 추천 대상 사용자가 이미 관람한 영화 ID 목록을 고유하게 유지하고,
      후보 필터링 시 .find() 기능을 통해 이진 탐색 속도(O(log N)) 성능을 보장할 때 사용.
  - std::map
    * key를 movieId, value를 누적 가중치 추천 점수로 매핑하여, 다수의 이웃 사용자로부터 발생하는
      복합 영화 점수를 단일 컬렉션 내에서 동적으로 병합 및 누적 처리할 때 활용.
  - Lambda Expression (람다식)
    * std::sort 알고리즘 적용 시 별도의 비교 함수나 구조체(Functor)를 정의하지 않고,
      오름차순/내림차순 사용자 정의 정렬을 인라인 코드 블록 내에서 직관적으로 처리하기 위해 필수 사용.

4. 시스템 신뢰성 강화를 위한 필수 예외 및 엣지 케이스 가이드
--------------------------------------------------------------------------------
다양한 런타임 입력 환경에서 크래시를 방지하기 위해 최소 2가지 이상의 방어 메커니즘이 코드 내에 구축되어야 합니다.

  - Case A: 신규 사용자 및 평점 부재 (Cold Start 예외)
    * 대상자가 새로 가입하여 평가한 영화 데이터가 0개인 상황을 조기에 탐지하여 즉시 빈 vector를 반환하도록 조기 종료(Early Return) 처리.
  - Case B: 임계 이웃 숫자 부족
    * 지정된 타겟 값인 K명보다 시스템 내의 유효 사용자 수가 적은 경우, 에러를 내지 않고 현재 확보 가능한 최대 인원수만큼만 이웃으로 수용하여 연산 완료.
  - Case C: 영화 풀 고갈 상황 및 추천 범위 예외
    * 상위 이웃들의 미관람 영화 추천 가능 총수가 최종 타겟 개수인 N개보다 적게 발굴되는 경우, 크래시 없이 현재 수집 가능한 개수만큼만 담아 유연하게 반환.
  - Case D: 공통 관람 이력 전무 상황
    * 타 사용자와 공통으로 관람하고 평가한 영화가 단 한 편도 발견되지 않아 유사도 매칭 점수를 측정할 수 없을 때, 이를 기본 불일치 처리하거나 패널티 상수를 부여해 연산 에러 무력화.
